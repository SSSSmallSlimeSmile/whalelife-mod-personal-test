# 左侧分栏游标（会话刻度轨）

## 现象

长会话里想回看前面某一段，只能一直往上滚。左侧原本有一列摘要，宽度 200px，占掉不少横向空间，缩到窄屏就挤得厉害。

## 触发原因

两件独立的事叠在一起：

**一、摘要栏占宽是固定的。** 200px 从不收，窗口窄的时候聊天区被压。

**二、滚动位置没有指示。** 聊天区很长，用户不知道自己处在整段对话的什么位置，也没有能点的定位点。

## 演化过程（几轮才定下来）

1. 200px 摘要栏 → **22px 窄条**：省空间，但只剩颜色块，看不出是什么
2. 窄条 → **悬浮卡**：鼠标悬停展开,但位置计算在隐藏状态下失效（`getBoundingClientRect()` 全为 0）
3. 悬浮卡 → **18px 刻度轨道**：一屏一个刻度，等距排布，当前视口那段高亮
4. 最终：**等距刻度 + 跟随滚动**

## 中间踩的四个坑（都修了）

**一、滚动容器判断错。** 监听的滚动事件绑在了错的元素上，滚到底也不触发。

**二、隐藏时 rect 全为 0。** 侧栏折叠状态下量尺寸，拿到 0 高度，刻度全叠在一起。

**三、`ResizeObserver` 只 observe 一次。** 窗口尺寸变了不复算，刻度位置留在旧值上。

**四、`#messages` 每次 render 被换掉**，滚动监听还绑在旧节点上——表现是刷新后要好一次，之后又不动；`window.focus` 触发 `syncView()` 重载会话，一回到窗口就跳最新。

第四条最费时间。根因是节点被替换而监听器没重绑。

## 触发场景

- 长会话（几百条消息）回看
- 窗口从大变小、或从别的窗口切回来
- 折叠侧栏后展开

## 复现步骤

1. 打开一个长会话
2. 往上滚：改前左侧不动；改后刻度高亮跟着走
3. 切到别的窗口再切回来：改前跳回最新；改后位置保持
4. 拖动窗口宽度：改前刻度叠一起；改后重新等距排布

## 验证

本机实际确认：滚动跟随、切窗保持、缩放重算三项都正常。

## 应用注意

**这一份跟 `对话界面` 那份改的是同一批文件**（`app.js`、`styles.css`），基线必须对得上，否则冲突。如果只想取一部分，刻度轨和分页加载是两处独立改动，可以分开摘。
