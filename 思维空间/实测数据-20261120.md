# 思维空间技能组实测数据

记录时间：2026-11-20（Australia/Brisbane）
环境：WhaleLife 主干 + thinking-space 0.1.0，模型 mr-deepseek-v41-flash

## 一句话

把「搜索并读正文」这串动作存成一条技能后，一次工具调用跑完，
省掉一轮完整推理。代价是参数必须写对，写错一次就全赔进去。

## 一、同一件事，两种跑法

群聊里当天两次真实记录，查询词不同（原始数据，非受控实验）。

| 项目 | 原生调用 | 技能组 |
|---|---|---|
| 对话轮数 | 3 轮 | 2 轮 |
| input token 合计 | 71,269 | 48,127 |
| 墙钟时间 | 99.6 秒 | 17.7 秒 |
| 中间步骤是否需要模型思考 | 需要，每步一轮完整推理 | 不需要，按链直走 |

省：token −32%，时间 −82%。

时间差主要来自中间那一轮。原生模式要先想“读哪一条链接”，
那是完整的一轮推理，44–46 秒起步。技能内部按 `results[0].url`
直接往下走，0.7–0.9 秒。

## 二、反面：参数写错一次的代价

同一技能、同一查询词，我第一次把参数名写成 `query`
（技能声明的是「关键词」），校验器拦住，多跑一轮：

```
实际  22,609 + 23,212 + 23,375 + 25,518 = 94,714 token · 4 次请求
```

比原生模式还多 33%。省下的全赔进去。

已修：参数现在有 `name`（机器名 query）和 `label`（显示名 关键词）
两套，`aliases` 接住旧写法，两种都能调通。

## 三、单次调用的时间分布

2026-11-20 当天多次实测：

| 链 | 耗时 | 结果 |
|---|---|---|
| surf_search → surf_read | 1.4 秒 | ok，5 条结果 + 正文 |
| surf_search → surf_read（带 3 候选回落） | 2.1 秒 | ok |
| 5 步长链（搜索/读/再搜索/再读/查状态） | 2.4–3.4 秒 | 三次全通 |
| comfy_status → comfy_generate | 19–25 秒 | ok，出图 |

0.5–4 秒，三候选全废时一条链要 5 秒以上。

## 四、自动整理：从真实调用里学技能

调 `space_organize` 扫最近调用记录，按 n-gram 找重复工具链。

当天实测：

```
连做 3 轮 [ledger_today, surf_status]
→ 扫 67 条记录，存 1 条 auto-58hlh5（2 步）
→ 再跑一次，saved 0（幂等）
```

**最初完全学不到东西**，因为 surf/bilibili 那批读取类工具在测试里
标了 `transientResult: true`，宿主发事件时带 `transient: true`，
我的监听器第一行就丢弃。改后只记工具名和成败、不记参数和结果，
读取类工具才进得来。

已修的两个算法缺陷：

- **没连线的重复展开**：连做三轮同一个两步组合，n-gram 同时产出
  2 步、3 步、4 步三个版本（`a,b`、`a,b,a`、`a,b,a,b`）。
  改成短链能覆盖长链就不存长链。
- **错位周期漏判**：`[a,b,a]` 对 `[a,b]`，从下标 0 对齐判不出。
  改成检查所有偏移量。修之前确实存出过一条 3 步的半周期链。

## 五、自动精简：跑熟了会变短

一条链跑通后回头看，哪一步白跑就砍掉。

删除条件（四条全满足）：

```
一  这一步这次跑成功了
二  它的输出没有被后面任何步骤引用
三  它不是最后一步
四  它的工具不需要确认（danger 为 safe）
```

实测：`ledger_today → comfy_status → surf_status` 跑一次后
3 步变 2 步（rev 2），删掉的是 `ledger_today`，因为没人用它的输出。

**逐步变短，不是一次砍到底**：4 步的链跑一次变 3 步，再跑变 2 步。
第一版一次删过头，`validateSkill` 拒绝（复合技能至少 2 步），
异常被 catch 吞掉，表面看什么都没发生。现在删到剩 2 步就停手，
catch 也从静默改成写日志。

## 六、候选回落砍枝

`$try` 里写多个候选，执行器按顺序试，第一个成功就采用：

```json
"url": {"$try": ["${n1.data.results[0].url}",
                 "${n1.data.results[1].url}",
                 "${n1.data.results[2].url}"]}
```

统计每次哪个候选命中，连续 3 次都是第一条 → 砍掉后面从没命中的。

实测 `probe-cut` 连跑三次全命中文首，第三次跑完：

```
trimmed: { cut: [{ key: "n2.url", kept: "${n1.data.results[0].url}", droppedCount: 2 }] }
技能 revision 1 → 2，定义真被改写
```

## 七、失败识别

工具返回 `ok: true` 但内容其实是失败句，执行器要能认出来。

判定分两档：

```
强词（任意长度 ≤300 字）  没在跑 / 未启动 / 已停止 / 显存不够 /
                          低于阈值 / 超过上限 / 请先启动 …
弱词（仅 ≤60 字短句）      失败 / 错误 / 无法 / 找不到 / 拒绝 /
                          error / failed / denied …
```

长正文不参与弱词判定，所以 `surf_read` 读回来几千字网页里
出现“错误处理”这类词不会误判。单测 8/8 通过。

端到端实测：

```
ComfyUI 停着 → n1 comfy_status failed「ComfyUI 没在跑（8188）」
              n2 没跑，整条链停在第一步
```

## 八、五态模型

| 状态 | 含义 |
|---|---|
| ok | 正常 |
| failed | 可重试 |
| empty | 上游无数据，后续步骤未启动 |
| skipped | 这一步没结果但不影响后面，已继续 |
| uncertain | 结果未知，不得自动重试 |
| blocked | 缺前置条件（副作用步骤未确认等） |

`uncertain` 用真超时验的：`see_now` 设 3 秒超时，3,015 ms 后记
`uncertain`，不再等也不重试。

全部步骤都跳到 skipped 时，整体抬成 `failed`——否则一条什么都没
干的链会显示成“没事”。

## 九、没验过的

- 8 步以上长链
- 并发跑多条技能
- 自动整理在真实使用里长期能不能产出有用的技能（当天存下的
  多数来自我的调试操作，不是真实任务）
- 页面视觉只验了 HTML 元素存在，没在浏览器里看过排版
- `$try` 砍枝按单次运行累加，没有跨会话的长期统计
