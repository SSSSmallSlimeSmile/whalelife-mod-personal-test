# WhaleLife 本地改动（未完成 / 需要动主干）

这个库放三类东西：

1. **还没完全验通的插件**——能独立加载，但装到别人机器上有已知风险
2. **需要动主干的补丁**——不是插件能解决的部分，只能改 `core/`
3. **改动说明文档**——每份都写现象、原因、修法、验证

成品插件在另一个库：[`whalelife-mod-personal`](https://github.com/SSSSmallSlimeSmile/whalelife-mod-personal)

> ### 强烈推荐安装前端渲染组件
>
> 就是 `packages/02-frontend.patch`（只改 `core/ui/` 六个文件，不碰后端）。
>
> **不装**：聊天页只认纯文本，模型回一张表格，你看到的是满屏竖线；粗体、标题、列表、代码块、链接全是原样符号。
> **装上**：Markdown 表格、标题、列表、引用、分割线、链接、粗斜体、行内代码、代码围栏都在页面上正常显示。
>
> 顺带还带了三样用着舒服的：
>
> - 思考中的颜文字提示，不再是干等
> - 左侧会话栏的等距刻度与悬浮卡
> - 回复前的念话按钮（喇叭图标）
>
> 聊天里回表格、贴代码是常事，不装就是看着难受。
>
> **注意**：它和 `01-functional.patch` 不重叠，可以单独 apply；如果只想要界面好看、不动后端，只装这一份就行。

## 先说清楚：验证范围

这个库里的补丁和文档，**只在本人那台 Windows 电脑上跑过**。没有在手机上跑过，也没有在第二台电脑上跑过。

补丁尤其要小心——基线绑死，换台机器、换个版本就可能全废。看到“能用”，意思是“在我这台机器上能用”，不是“在哪都能用”。

## 二、补丁

分三份，都在 `2ee7b09` 干净树上实测过。

| 文件 | 内容 | 基线 |
|---|---|---|
| `all-20261119.patch` | 全部改动，190,692 字节，31 文件，+2803 −111 | `2ee7b09` |
| `packages/01-functional.patch` | 通用看门狗 + 后端功能 + 测试，116,974 字节，25 文件 | 同上 |
| `packages/02-frontend.patch` | 只碰 `core/ui/` 的六个文件，73,718 字节 | 同上 |

`all` 就是两份首尾拼接。应用一份即可，或者按 01 → 02 的顺序应用，结果一样。

三份都能单独用，也都能单独编译：

```
01 单独 apply                    tsc --noEmit  0
01 → 02 顺序 apply               tsc --noEmit  0
all 一次 apply                   tsc --noEmit  0
```

**注意**：补丁截止 2026-11-19 06:00，含把密钥挪进环境变量的 ENV 引用、聊天页念话按钮、账本页面插件化、插件页若干修复、`core/llm.ts` 允许单次调用覆盖参数（供识图关掉思考），以及 `core/session.ts` 里的循环守卫三道闸（同参重复 3 次、轮数 100、单轮 20 分钟、上下文 85% 提前告知），还有 `core/tool-protocol.ts` 的工具调用泄漏检测与恢复（详见 `安全/工具协议清洗-v2-20261119.md`）。不含 14 个一次性调试脚本（`cdp_*.cjs`、`tools/kan-edit-rail.ps1`、`scripts/*-20261115.mjs` 等），它们仍在本地仓库里，但没打进补丁。

补丁只收进来能独立讲清楚的部分。本地还有一批扩展没有放进来，也没有写成文档——那部分是我们自己还在磨的东西，不想占作者的设计空间，作者那边要统一改就按自己的思路来。补丁在这些位置已经回到上游原样，不会带进去。

**一处更正**：早先的 `all-20261118e.patch` 和 `02-local.patch`，剥的时候漏了 `core/index.ts` 里对 `model-router.ts` 的 import 和注册，那个文件又被排除在补丁外，结果应用后`tsc` 报 `Cannot find module './model-router.ts'`。**那一版是编译不过的。** 现在这几行已经剥干净，上面那三行验证是重跑过的。

### 工具协议清洗（已并入上面三份）

这部分现在已并进 `all-20261119.patch` 和 `01-functional.patch`（`core/tool-protocol.ts` + `core/session.ts` + `core/web.ts` + 测试），不再单独发补丁。它解决的是：

- 模型把工具调用写进正文时（`content` 里出现 `｜｜DSML｜｜` 标记），界面不再把它当正常回复显示
- 名字能对上本轮声明的工具时，**恢复成真正的调用执行**，而不是当噪声扔掉
- 救不回来才剥除，存进历史的永远是干净正文
- 剥完是空的时候给一句说明，不再把整轮聊天变成报错

配套说明是 `安全/工具协议清洗-v2-20261119.md`（含根因、复现步骤和回放数据）。旧的 `工具协议清洗-20261119.md/.patch` 是单文件版本，基线 `f2a097d`，已被这一版取代，保留在目录里只作记录。

## 四、给别人用之前先读这段

**一、基线绑死。** 补丁对 `2ee7b09`。你那边版本不同就会冲突，`git apply` 直接失败。没有“自动适配”这回事。

**二、配置不在补丁里。** `config/` 在 `.gitignore`，里面的东西都不跟着走。装上等于半套：有些开关没有默认值，得自己照着代码补。

**三、改的是 `core/`。** 上游一更新就全废。这是补丁不是插件，没有别的办法。

**四、验证范围。** 所有补丁只在本人一台 Windows 电脑上跑过，没有跨机器验证。
