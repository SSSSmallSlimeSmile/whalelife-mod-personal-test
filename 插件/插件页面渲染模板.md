# 插件页面渲染模板

> 来源：2026-11-20 统一 thinking-space / comfy / ledger / qq-group 四页样式时整理。
> 每一条都对应一次真实踩坑，不是凭空定的规范。
> 新插件照抄这一份，能避开大部分视觉和路由问题。

## 一、页面是装在 iframe 里的

宿主把插件页面放在 `<iframe width="100%">` 里渲染。

**推论：不要在 iframe 内部再套一层限宽居中。**

```css
/* 错 */
.wrap { max-width: 900px; margin: 0 auto; padding: 26px 24px; }

/* 对 */
.wrap { max-width: none; margin: 0; padding: 26px 24px; }
```

900px 在 1280px 宽的内容区里居中的结果是两边各空 190px，看起来
像"卡片没对齐、左边多一块"。2026-11-20 之前在 thinking-space、comfy、
ledger 三个页面都出现过，用户三次截图指出来。

**注意区分**：`@media (max-width: 760px)` 里的 `max-width` 是断点，
不是容器限宽，**不要动**。

## 二、CSS 变量必须用宿主那套名字

宿主 `core/ui/styles.css` 里定义的是：

```css
--surface   卡片/面板底色
--line      分割线
--accent    主色        #6158d9
--text      正文
--muted     次要文字
--bg        页面底色
```

插件里常见错误是写 `var(--panel, #fff)`——宿主**没有** `--panel`，
于是永远回落到硬编码 `#fff`，宿主哪天改色它不跟。

```css
/* 错 */  background: var(--panel, #fff);
/* 对 */  background: var(--surface);
```

## 三、引宿主样式表，不要自己写一套

```html
<link rel="stylesheet" href="/ui/styles.css">
```

宿主主题是一套浅色变量。插件自建 `#f5f6fa` 这类硬编码色，深浅切换
时对不上，也会和相邻页面不像一家人。

需要额外样式时，用带前缀的类名追加，别覆盖宿主类：

```css
.pg-wrap { … }
.pg-pair { … }
```

前缀 `pg-` 是为了躲开宿主 `.row` 这类通用名——之前 `.row` 撞过
`styles.css:477` 的规则，标签被挤到左边。

## 四、卡片骨架

宿主标准结构：

```html
<section class="panel">
  <div class="panel-header">
    <h2>标题</h2>
    <button class="btn">操作</button>   <!-- 可省 -->
  </div>
  <div class="panel-body">
    ……
  </div>
</section>
```

`.panel-header` 自带下边框和左右内边距，`.panel-body` 自带内边距。

**不要**自己造 `.xxx-panel > h2` 这种平级结构，会缺边框、缺间距，
和记忆管理页看着不一样。

## 五、徽章

宿主 `.badge` 是 `10px / 5px 圆角 / 实底`，另有 `.badge.green`、`.badge.red`
两个色。

```html
<span class="badge green">safe</span>
<span class="badge red">待核实</span>
```

插件自造 `12px / 999px 圆角 / 描边` 的圆胶囊，和宿主并排就是两种风格。
统一用宿主那套。

## 六、路由：page 和 api 不是一回事

这是最容易按直觉写错的一条。

```ts
ctx.web.page(path, handler)   // 只注册 GET
ctx.web.api(path, handler)    // 只注册 POST
```

在 `page()` 里写 `if (req.method === "POST")` 是**无效的**，那个分支
永远走不到，表单提交会 404，页面显示"接口不存在"。

正确写法是拆成两条：

```ts
ctx.web.api("/plugins/xxx/settings", async (req, res) => {
  // 处理 POST，保存后
  res.writeHead(303, { Location: "/plugins/xxx/settings?saved=1" });
  res.end();
});

ctx.web.page("/plugins/xxx/settings", async (req, res) => {
  // 只负责渲染
});
```

表单 `action` 写同一个路径就行。

## 七、导航入口

**现状**：插件自己声明 `navigation: true` 会在左侧「插件页面」组里出现一条。
想挂到「管理」组（记忆管理、插件管理、运行日志那一组），目前没有公开接口，
只能改 `core/ui/index.html` 硬加一行。

改 `app.js` 判断入口是否显示时，注意别用 `p.navigation` 当条件——

```js
/* 错：navigation 改成 false 去重，结果两边都不显示 */
const page = pages.find((p) => p.path === path && p.navigation);

/* 对：只要页面存在、插件 active 就显示 */
const page = pages.find((p) => p.path === path);
```

2026-11-20 踩过一次：为了去掉「插件页面」组里的重复项，把
`navigation` 设成 `false`，结果「管理」组那条也一起消失，整个入口没了。

**待上游兼容**：正式做法应该是插件声明自己挂哪个导航组，而不是
前端写死一个中文名和路由。等作者开口。

## 八、自检清单

新插件页面写完，逐条过：

```
[ ] 引用了 /ui/styles.css
[ ] 没有任何 max-width 限宽（断点除外）
[ ] 没有 var(--panel) / var(--border) 这类宿主不存在的变量名
[ ] 卡片是 .panel > .panel-header + .panel-body
[ ] 徽章用 .badge + .green/.red
[ ] 附加类名带 pg- 前缀
[ ] 表单保存走 ctx.web.api()，不是 page() 里的 method 判断
[ ] 保存后 303 跳回，刷新能看到新值
[ ] tsc 通过（注意 tsconfig 是否包含 plugins/**
[ ] 页面 GET 200，抓 HTML 数一遍关键元素在不在
```
