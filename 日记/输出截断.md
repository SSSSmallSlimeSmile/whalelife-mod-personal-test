# 日记：输出截断（能挑进去，压不出来）

提交：`e83191f`（`core/session.ts`）、`2e0377b` 前后也相关

## 症状

```
[WARN] 日记整理已暂停，原文与已保存日记保留
{"reason":"日记输出达到上限而被截断，原文保留；请调整容量后显式重试"}
```

一次之后整个会话的日记就停了，不会自己恢复，要人显式清标记。

## 触发原因：输出上限写死，压缩比没上限

挑原文那段（`session.ts`）：

```
desired = inputTokens - target + outputTokens
outputTokens = Math.max(256, Math.min(8192, Math.floor(requestBudget * 0.1)))
```

`requestBudget` 约 197952，×0.1 = 19795，被 `min(8192, …)` 截成 **8192**。

**挑原文只看"装得进模型上下文"，没看"压得进输出上限"。**

实际撞线那次：

```
desired ≈ 80248 token 原文
输出上限  8192 token
压缩比    1:9.8
```

模型写到一半就到上限，`finish_reason` 变 `length`，代码判暂停。

## 触发场景

- 会话很长，上下文接近阈值，`desired` 自然大
- 上一次日记写得很细（5774 字那种），模型倾向继续写长
- 原文又多又散，压缩不了

昨天那次能成（`sources: 461`，5774 字符），不是因为比例合理，是因为挑出来的原文刚好装得下。

## 改动

**一、加压缩比上限**

```
const DIARY_SOURCE_RATIO = 3;
const sourceCeiling = outputTokens * DIARY_SOURCE_RATIO;
const desired = diaryPrefix(remaining, Math.min(inputTokens - target + outputTokens, sourceCeiling), cost);
```

先试过 6（24576 → 49152），还是撞。改成 3 才过。

**二、原文太少就别试**

```
const MIN_DIARY_SOURCE_TOKENS = 4000;
if (selectedCost < MIN_DIARY_SOURCE_TOKENS) {
  logger.info("日记整理", { status: "skipped", reason: "budget_too_small" });
}
```

预算不够时不该硬挑两条去撞墙。不够一个最小批量就跳过，不请求模型、不记失败、不暂停。

## 为什么必须两条一起改

只加比例上限，预算剩 9896 时仍然会挑出 2 条（几百 token），生成 2140 字的日记，然后被 `memory-diary.ts:150` 那道检查拦住：

```
if (diaryTokens >= originalTokens) throw new DiaryError("生成日记未节省上下文容量，原文保留；请调整范围后显式重试");
```

这道检查本身没错——压不动就不该写。错在**不该进到这一步**。

## 复现步骤

**复现截断**：

1. 让上下文涨到触发线以上（本机 20 万 × 80% = 16 万）
2. 预算充足（`daily_memory_tokens` 设 400000）
3. 把 `DIARY_SOURCE_RATIO` 临时改成 10

期望日志：`{"status":"failed","sources":158,"reason":"日记输出达到上限而被截断…"}`

**复现 budget_too_small**：

1. `daily_memory_tokens` 设成 200000 且已用掉大半（剩不到 9000）
2. 触发整理

期望日志：`{"status":"skipped","reason":"budget_too_small"}`

## 验证

比例 3 + 最小批量 4000，实跑：

```
2026-11-16T19:39:36.765Z [INFO] 日记整理
  {"status":"written","sources":158,"remaining":398,"budget":200000}
```

`state.json`：

```
diaries 2
  0  5774 字符  2026-11-16T11:02:30Z
  1  6152 字符  2026-11-16T19:38:50Z
failures {}     ← 没有暂停标记
```

同一批 158 条原文：比例 6 时截断，比例 3 时写完。

## 应用注意

**`8192` 建议改成配置项**（如 `diary_max_output_tokens`），别写死。不同模型的输出上限不一样，写死一个数总会有撞上的一天。

**暂停标记要手工清。** 位置在 `knowledge/state.json` 的 `diary_failures`，清成 `{}` 即可。重启不会清它。

**比例 3 是跑通的下限，不是最优。** 代价是每次记得少一些、篇数变多。想记细一点可以调回 4–5，但要确认不撞 8192。
