# 日记：请求参数被中转改坏

提交：`5960abd`（`core/memory-diary.ts`，+4 −1）

## 症状

日记请求发出去报参数错误，或者中转直接 400。

## 触发原因：按模型名猜是不是 DeepSeek 官方

原文：

```ts
if (host !== "api.deepseek.com" && !/^deepseek[-/]/i.test(provider.model ?? ""))
  return { ...provider, parameters };
Object.assign(parameters, { response_format: { type: "json_object" }, thinking: { type: "disabled" } });
delete parameters.reasoning_effort;
```

逻辑是：如果不是官方域名 **且** 模型名不像 deepseek，就原样转发；否则改参数，塞 `thinking: {type:"disabled"}`、删掉 `reasoning_effort`。

**问题在走中转的情况**：MiraRouter 上的模型名是 `deepseek-v4.1-flash`，正则命中，于是被当成官方端点处理——塞进去的 `thinking` 它不是那个意思，`reasoning_effort: "none"` 还被删了。

## 触发场景

- 用中转（MiraRouter、各种 API 聚合站）
- 模型名里带 `deepseek`
- 那个中转不认 `thinking` 字段，或者靠 `reasoning_effort` 控档

## 改动

```ts
// Only the official endpoint is documented to accept `thinking` / `response_format` here.
// Relays such as MiraRouter carry their own `reasoning_effort` (e.g. "none") and may not
// understand `thinking` at all, so their parameters are forwarded untouched.
if (host !== "api.deepseek.com") return { ...provider, parameters };
```

**只看域名，不看模型名。** 中转的参数原样转发，不动。

## 验证

`tsc --noEmit` 退出码 0。

实际日记请求成功（本机改完后 `status: "written"` 多次出现），没有参数错误。

## 同类问题

`core/llm.ts` 里的 `thinkingToolHistory` 是同一个毛病，同样按 `/^deepseek[-/]/i` 猜。那处在合并上游时保留了本地写法（只认 `api.deepseek.com` 或显式 `thinking.enabled`）。

**以后加新逻辑时，别再按模型名猜端点能力。** 模型名控制在中转手里，随时可能改。
